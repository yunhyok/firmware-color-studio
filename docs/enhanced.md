# Enhanced profiles

Firmware Color Studio exports an XMP profile, its matching base DCP and the source recipe in one ZIP. Use **Import Profiles and Presets** in Adobe Camera Raw. For manual installation, place the DCP in the CameraRaw/CameraProfiles directory and the XMP in CameraRaw/Settings. The XMP matches the base DCP by its embedded name, so keep both files when moving the profile between computers. The XMP and its recipe filenames include the mode and profile UUID. The base filename includes the camera pack version, a v2 marker, and a digest of the firmware colour matrix and calibration matrices. Compatible toning variants can share one base; a different colour matrix or calibration requires a different base. [Adobe Camera Raw installation instructions](https://helpx.adobe.com/camera-raw/desktop/edit-and-enhance-images/tone-and-color/adjust-color-rendering-camera-camera.html), [export implementation](../src/firmware_color_studio/enhanced.py)

The v2 base DCP applies the recipe's firmware CC0 matrix in intermediate ProPhoto coordinates, with a linear tone curve, an identity LookTable and the +0.5 EV profile offset. Adobe's intermediate clipping then aligns with the firmware's pre-gamma clipping. The paired XMP applies gamma, YC conversion, chroma suppression and the selected toning offset, then converts the result to real ProPhoto RGB. Gold uses its three verified hardware gamma responses. The recipe's optional ColorMatrix1/2 pair remains in the DCP for camera-specific white balance calibration. **Use the DCP and XMP together: the base DCP alone does not produce correct colours.** See the [v2 transform derivation and SDK normalization](lut-fidelity.md#two-distinct-corrections).

Version 0.1.4 gives each re-exported XMP a new UUID and pairs it with the existing v2 base DCP. The table fingerprint changes when the exported table values change. Monochrome retains its v0.1.3 table in both camera colour spaces. Previously exported bundles retain their original behavior. To obtain the correction, open the saved recipe in the updated app, export the bundle again and import the resulting ZIP. If keeping both versions installed, use a distinct profile name for the updated recipe so they are easy to distinguish. Existing user profiles and files do not need to be deleted. The embedded name, including the v2 base marker, matches the required DCP. Standalone DCP exports retain their existing construction. [Profile identity and compatibility](lut-fidelity.md#two-distinct-corrections)

The 32³ RGB table uses ProPhoto RGB primaries with the sRGB transfer function, matching the size limit documented for Adobe's enhanced profile authoring workflow. Each output channel is rounded to unsigned 16-bit code values. The XMP uses the Adobe DNG SDK RGB table stream, zlib container, XMP base-85 encoding and MD5 table identifier. The app's renderer uses the same quantized samples and tetrahedral interpolation. The 16-bit quantization step is 1/65535 in encoded table space. [Adobe Profiles SDK and DNG SDK](https://www.adobe.com/support/downloads/dng/dng_sdk.html)

## Preview and validation

### v0.1.4 chroma-suppression boundaries

At certain luminance values, the firmware switches between two chroma gains with a small step. A 32³ LUT interpolates continuously across that step. When an output channel is near sRGB black, even a small linear RGB difference can become visible in the encoded channel. In HARUBENI, Adobe RGB, tint 1, highlight contrast −4, the largest red error on the original sample set fell from 10.674/255 in v3 to 6.462/255 in v4. At the v3 worst input the firmware model gives red 0.01458, the v3 export gives 0.05644 and v4 gives 0.03992. [Firmware gain trace and red-channel plot](https://yunhyok.github.io/pentax-k3iii-firmware-analysis/analysis/gold-enhanced-profile.html#lut-v4)

The builder starts with the quantized v3 table. A vertex is eligible when its neighbours span a firmware gain step and at least one neighbouring linear sRGB channel reaches 0.0031308 or below, the linear segment of the sRGB transfer function. For adjacent cells with more than 2/255 encoded sRGB error at a node or tetrahedral edge midpoint, the builder evaluates the firmware model at quarter-cell intervals. Four refinement passes give larger errors more weight and preserve signed values outside the sRGB gamut. The export uses half the resulting change. It preserves the 16-bit values on all twelve cube edges and the neutral diagonal and still exports a single 32³ ProPhoto table. [Builder](../src/firmware_color_studio/enhanced.py) · [Serialized export tests](../tests/test_enhanced.py)

### v0.1.3 midpoint sampling

Version 0.1.3 evaluates the firmware transform at the 32³ nodes and at the midpoints of all edges used by Adobe’s tetrahedral interpolator. Together these points form a 63³ grid in encoded LUT coordinates. At a midpoint Lightroom interpolates the two endpoint codes with equal weights. The builder compares that prediction with the firmware evaluation in encoded ProPhoto coordinates and distributes the difference to the eligible endpoints. Four damped passes precede one final 16-bit quantization. Interior nodes use all seven positive edge directions and their reverses. Face nodes use only edges in that face. The twelve cube edges and the neutral diagonal retain their original firmware samples throughout. This keeps the original neutral response, including intentional Gold and toning colours. The exported XMP carries one 32³ table. [Builder and interpolation](../src/firmware_color_studio/enhanced.py) · [SDK stages and source locations](lut-fidelity.md#supported-format-and-limits)


The offline renderer reads the serialized DCP, reproduces Adobe's matrix rounding and D50 normalization, and applies BaselineExposure plus the base DCP offset once. A positive total scales the intermediate RGB ramp before the LUT. A negative total shapes the base tone curve before the XMP LUT, following the DNG reference exposure operation and Adobe's documented late placement of RGB LUTs. This negative-exposure operation preserves white; it is not equivalent to uniformly scaling firmware input. The preview models these stages on white-balanced camera RGB and displays SDR sRGB. [SDK source references and processing limits](lut-fidelity.md#supported-format-and-limits)

The v0.1.2 LUT sampled the firmware transform at the 32³ grid nodes. Its deterministic sweep of 198 recipes and 18,666,801 synthetic RGB triplets includes the full input cube, clipping boundaries, every available tint and selected slider extremes in both colour spaces. Across those recipes, the largest individual-recipe mean/p95/p99/maximum error is 0.380/1.232/2.938/29.481 in encoded sRGB channel units on a 0–255 scale. These finite-sample results do not establish a bound for all possible inputs. Adobe Camera Raw and Lightroom also apply their own demosaic, process version and edits.
